BakiBondhu — Status & Tracking

How to check if the app is live, which version is out, how many people use it, and whether the server is healthy — all in one place.

🔐 Admin panel 🩺 Health 🏷️ Version API 📦 Releases 🌐 Site 💻 Web app

1 How many people use my app?

source of truth

Every account syncs to your server, so the Admin panel is the real number.

Open the Admin panel and log in. The dashboard shows total shops, new signups, outstanding credit across all shops, and recent activity. The Shops list shows each owner, mobile and subscription expiry, with suspend / delete / reset-password.

Since v0.1.20 an account is required to use the app, so this counts your true active user base.

Deeper look: phpMyAdmin (InfinityFree control panel) → database if0_42877652_bakibondhu → Browse businesses / users. Sort by created_at for signups over time, or country to see where owners are.

2 Is it live & what's the latest version?

  • One-glance check — the version endpoint returns the current numbers as JSON: /api/v1/app/version → android.version / android.build and web.build. This is what installed apps compare against for the in-app "Update available" prompt.
  • Landing page shows the current version in the download caption.
  • Latest APK always resolves here (never goes stale): …/releases/latest/download/BakiBondhu.apk

3 How many downloads / installs?

GitHub Releases shows a download count per release asset. Total per release from the command line:

gh api repos/mrofiqul/bakibondhu-app/releases \
  --jq '.[] | {tag:.tag_name, downloads:([.assets[].download_count]|add)}'

Downloads ≈ installs from the website/GitHub (a proxy, not exact). The Admin signup count in §1 is the better "who's actually using it" number.

4 Is the server healthy?

  • Health check: /health → returns a small OK/JSON. If it returns the landing page HTML instead, the API router was overwritten (see the deploy-paths note in the dev docs).
  • Hosting / uptime: the InfinityFree client area (infinityfree.com) shows account status, disk/bandwidth, and any suspension. Free hosting can pause under very high traffic or daily-hit limits.
  • Database: phpMyAdmin — browse tables, run queries, check size.

5 F-Droid listing status

free store

After you open the merge request (see the free-distribution guide).

  • Your merge request on gitlab.com/fdroid/fdroiddata — shows review comments and a CI pipeline (lint + test build). Green pipeline + maintainer approval → merged.
  • Build status after merge: monitor.f-droid.org (search the package) shows whether each version built.
  • Public app page (once live): f-droid.org/packages/com.bakibondhu.bakibondhu/
  • New releases: tag the source repo (git tag v0.1.x && git push --tags) and F-Droid auto-detects it — no new MR.

6 Google Play status

when you pay $25

In the Play Console (play.google.com/console):

  • Dashboard — installs, uninstalls, ratings, crashes over time.
  • Publishing overview / Releases — review status of each submission ("In review", "Live", "Rejected" + reason).
  • Statistics — active devices, countries, Android versions.
  • Ratings & reviews — reply to users. Policy status — any compliance flags.

7 Amazon / Samsung

If you upload there, each has its own console dashboard (installs, reviews, review status): Amazon developer.amazon.com, Samsung seller.samsung.com.

✓ Quick weekly routine

  1. Admin panel → new signups + total shops (are people joining?).
  2. /health up? · InfinityFree client area → account not suspended?
  3. GitHub releases → download counts trending?
  4. On F-Droid/Play → check the store dashboard for reviews / crashes / review status.
  5. Confirm the latest release matches what /api/v1/app/version advertises.

⚠️ Watch the free host's limits. As usage grows, InfinityFree's daily hits / bandwidth caps are the most likely thing to interrupt the backend. If you hit them often, that's the signal to move to paid hosting.
